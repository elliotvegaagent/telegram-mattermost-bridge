# Telegram ↔ Mattermost Bridge

Надёжный двусторонний мост между одной или несколькими парами «Telegram-группа ↔
выделенный Mattermost-канал». Новые сообщения становятся корневыми постами, а
ответы сохраняют принадлежность к Mattermost-треду.

## Как устроен диалог

- Новый пост Mattermost публикуется новым сообщением Telegram.
- Новый пост Telegram создаёт корневой пост Mattermost.
- Mattermost thread reply становится Telegram Reply к якорю диалога.
- Telegram Reply к связанному сообщению попадает в тот же Mattermost-тред.
- Telegram Reply к неизвестному сообщению создаёт новый тред с короткой цитатой.
- Редактирование связанного текстового сообщения обновляет уже созданную копию без
  нового поста. Если связь неизвестна, исправление остаётся отдельной заметкой.
- Сообщения ботов моста не пересылаются повторно.

## Персонализация и реакции

- У каждого автора есть стабильный цветной маркер, вычисляемый из ID пользователя.
- Для Telegram-автора мост получает самую маленькую профильную фотографию и передаёт
  её Mattermost как встроенный `data:` URL. Telegram-токен при этом не раскрывается.
- Если Mattermost разрешает интеграциям переопределять имя и иконку, пост отображается
  с именем и аватаром Telegram-автора. Независимо от этой настройки текст входящего
  сообщения всегда начинается с `Имя Telegram-автора: текст`.
- Базовые реакции синхронизируются в обе стороны: `👍`, `👎`, `❤️`, `🔥`, `🎉`,
  `✅`, `👀`, `😂`. Добавление и снятие учитываются отдельно для каждого автора.
- На целевой платформе реакция технически принадлежит bridge-боту: API Telegram и
  Mattermost не позволяют поставить её от имени исходного пользователя.
- Mattermost сохраняет несколько разных реакций. Telegram разрешает обычному боту
  выбрать только одну реакцию на сообщение, поэтому там показывается последняя
  актуальная реакция; после её снятия восстанавливается предыдущая.
- Служебная `✅` доставки не ставится, чтобы она не занимала единственное доступное
  боту место для синхронизируемой реакции.
- Аватар ограничен 128 КиБ. Отсутствующий или слишком большой аватар не блокирует текст.
- Ответ сотрудника в Telegram показывается компактно: `Имя сотрудника : текст`, без
  технического названия платформы и Mattermost username.

Для динамических имён и аватаров Mattermost-администратор должен включить в
**System Console → Integrations → Integration Management** настройки **Enable
integrations to override usernames** и **Enable integrations to override profile
picture icons**. Webhook создавать не требуется: bridge использует эти свойства
через существующий bot account.

Мост передаёт текст, фото, документы, видео, аудио, voice и animation как
скачиваемые файлы. Текстовые исправления и базовые реакции синхронизируются в обе
стороны. Произвольные/custom emoji, платные реакции, опросы как интерактивные
опросы, замена уже переданного файла, синхронное удаление чужих Telegram-сообщений
и отображение стикеров как стикеров не поддерживаются. Реакции Mattermost,
поставленные во время разрыва WebSocket, не восстанавливаются из истории постов.

## 1. Создание Telegram-бота

1. Создайте бота через `@BotFather` и сохраните токен.
2. Выполните `/setprivacy`, выберите бота и установите `Disable`.
3. Если бот уже был в группе, удалите и добавьте его заново после изменения
   Privacy Mode.
4. Добавьте бота в группу как администратора: Telegram отправляет ботам события
   изменения реакций только при этом статусе. Достаточно минимального набора прав.
5. Отправьте в группу тестовое сообщение.
6. Получите `chat.id` из Bot API. При сохранённом токене в переменной окружения:

   ```bash
   curl --silent "https://api.telegram.org/bot${TG_BOT_TOKEN}/getUpdates"
   ```

   У supergroup идентификатор обычно отрицательный и начинается с `-100`.

Бот принимает события только от групп, перечисленных в `TG_CHAT_ID` или
`BRIDGE_PAIRS`; другие группы и личные чаты игнорируются.

## 2. Создание Mattermost-бота

1. System Admin включает **Integrations → Bot Accounts**.
2. Создайте отдельного bot account и сразу сохраните access token.
3. Создайте или выберите приватный канал только для этого контрагента.
4. Добавьте bot account в команду и канал. Системные права и доступ ко всем
   каналам ему не нужны.
5. Скопируйте ID канала через REST API или инструменты администратора. Проверка
   ниже отклонит имя канала вместо ID.

## 3. Конфигурация

Самый простой способ — запустить интерактивный мастер. Он откроет нужные страницы,
покажет найденные ID чатов/каналов и сохранит секреты в локальный `.env` с правами
`0600`:

```bash
./scripts/setup_credentials.sh
```

Мастер можно безопасно запускать повторно: Enter сохраняет уже записанное значение.
Если мастер не подходит, создайте файл вручную:

```bash
cd telegram_mattermost_bridge
cp .env.example .env
chmod 600 .env
```

Заполните обязательные значения:

| Переменная | Назначение |
|---|---|
| `MM_URL` | Базовый HTTPS URL Mattermost |
| `MM_BOT_TOKEN` | Access token Mattermost bot account |
| `TG_BOT_TOKEN` | Токен от BotFather |
| `MM_CHANNEL_ID` | ID канала для режима одной пары |
| `TG_CHAT_ID` | ID Telegram-группы для режима одной пары |
| `BRIDGE_PAIRS` | JSON-массив пар; заменяет `MM_CHANNEL_ID` и `TG_CHAT_ID` |
| `DB_PATH` | SQLite-файл; в Compose оставьте `/data/bridge.db` |
| `MAX_ATTACHMENT_BYTES` | Локальный предел одного файла, по умолчанию 25 MiB |

Для нескольких контрагентов используются общие bot accounts и одна переменная:

```env
BRIDGE_PAIRS=[{"id":"default","tg_chat_id":-1001111111111,"mm_channel_id":"channel_a_id"},{"id":"customer-b","tg_chat_id":-1002222222222,"mm_channel_id":"channel_b_id"}]
```

`id` должен быть уникальным. Telegram-группа и Mattermost-канал могут входить только
в одну пару. При переходе существующей установки на `BRIDGE_PAIRS` сохраните для
текущей пары ID `default`: так продолжат использоваться её checkpoint и связи.
Новой паре при первом запуске ставится Mattermost checkpoint «сейчас»; старая история
канала не импортируется. Повторно выполнять `bridge init` для добавления пары не нужно:

```bash
docker compose run --rm bridge doctor
docker compose up -d --force-recreate
```

Секреты не передаются аргументами командной строки, не включаются в образ и не
пишутся в JSON-логи.

## 4. Проверка и первый запуск

Соберите образ и проверьте токены, каждую настроенную пару, членство ботов и SQLite:

```bash
docker compose build
docker compose run --rm bridge doctor
```

Инициализация намеренно удаляет накопленные Telegram updates и ставит
Mattermost checkpoint на текущий момент. Старая история не импортируется:

```bash
docker compose run --rm bridge init
```

Повторная инициализация запрещена. Для осознанного сброса checkpoint используйте
`init --force`; уже созданные связи сообщений в SQLite при этом сохраняются.

Запуск:

```bash
docker compose up -d
docker compose logs -f bridge
```

Проверка процесса и готовности:

```bash
curl --fail http://127.0.0.1:8080/healthz
curl --fail http://127.0.0.1:8080/readyz
```

`healthz` проверяет процесс. `readyz` возвращает HTTP 503, если Telegram или
Mattermost недоступен либо старейшее задание ждёт доставки больше десяти минут.
Количество dead-letter заданий остаётся видимым в поле `outbox.dead` ответа.

## Доставка и восстановление

Событие и checkpoint сначала фиксируются в SQLite, затем durable outbox доставляет
его второй платформе. Сетевые ошибки, HTTP 429 и 5xx повторяются с задержкой до
пяти минут. Постоянные ошибки 400/403 переводятся в dead letter, а в исходном
чате появляется предупреждение о недоставке.

После разрыва Mattermost WebSocket мост читает каждый канал от собственного checkpoint
с пятиминутным перекрытием. Уникальные event IDs подавляют повторную доставку.
Семантика остаётся at-least-once: авария строго между успешной внешней отправкой
и фиксацией её ID может дать один дубль.

SQLite работает в WAL-режиме. Для резервной копии остановите контейнер и
скопируйте volume либо используйте штатный SQLite online backup.

## Локальная разработка

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[test]'
pytest
```

Команды без Docker: `python -m bridge doctor`, `python -m bridge init` и
`python -m bridge run`.
